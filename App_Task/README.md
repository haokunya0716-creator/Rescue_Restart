# 小车运行流程

更新日期：2026-10-24。当前三个独立测试入口均已注释，使用正式按键流程，以整块安全区XY到位为终点；正式Y控制已恢复200 ms/3帧起步确认、换向先停车及滞回。比赛条款见 [RULES.md](RULES.md)，本流程仅用于当前调试，不代表有效送达或解锁其它物资。

## 当前模式与测试切换

当前 `Core/Src/main.c` 的三个测试入口均已注释，使用下方正式按键流程。`while(1)` 开头为：

```c
//if (App_ZoneXYHeading_Test(APP_TASK_TEAM_RED, 69.9f)) { continue; }
//if (App_ZoneY_Test(APP_TASK_TEAM_RED)) { continue; }
// if (App_Zone_Test(APP_TASK_TEAM_RED)) { continue; }
```

使用独立测试时，只取消所需入口的注释；测试蓝方时把队伍参数改为 `APP_TASK_TEAM_BLUE`。XY＋固定航向测试的第二个参数是场地标定后的绝对航向角，单位为度；当前保留参数为 `69.9f`。三种入口只能启用一个，启用后均独占主循环，不处理正式按键；原 `app_cargo_test.h` 是未调用的物块标定工具。

### 独立Y轴调参流程

实现文件为 `app_zone_y_test.c/.h`，不调用正式 `App_Task_Proc()` 或绿色控制函数。车头需要手动朝向本队整块安全区，测试不负责找区或左右纠偏。

```text
开机进入App_ZoneY_Test，建立180秒测试起点
    ↓ 停轮，前框按SERVO1_DROP落下（当前90°），摄像头50°，等待500 ms
读取Ozone可写的zone_y_tune参数；enable初值1，自动开始
    ├─ enable=0 → 立即停车，继续接收视觉
    ├─ 参数无效 → 停车，status=5
    └─ 参数有效 → 发送view_id，等待当前视角的本队整区（红5/蓝6）
           ├─ 图像不可用/过期/视角不符/本队整区丢失 → 立即停车，清PID历史
           ├─ 重复图 → 只运行轮速内环，不重复积分、不计算D
           └─ 有效新图 → 取第一个本队整区，中心Y归一化到480高
                  ↓ error=target_y-y
              |error|≤tolerance → 停车，清PID历史；偏离后可继续调整
              |error|>tolerance → 独立PID，以新图间实际秒数计算I和D
                  ↓ 前进/倒车限幅，非零输出施加最小速度（不超过对应上限）
              左轮目标=右轮目标=speed，持续循环；不运行X转向或航向外环
    ↓ 从首次进入测试起达到180秒
停车并保持接管主循环，status=6；再次测试需复位
```

在Ozone中加载本次生成的 `build/Debug/intelligent_rescue.elf` 并运行，向Watch添加 `zone_y_tune`、`zone_y_watch`。二者为全局 `volatile` RAM变量，Debug使用 `-O0 -g3 -gdwarf-4`。展开 `zone_y_tune` 后可修改：

| 成员（完整表达式前缀为 `zone_y_tune.`） | 编译初值 | 作用 |
|---|---:|---|
| `enable` | 1 | 0立即停车，1运行；不暂停180秒总计时 |
| `reset` | 0 | 写1清除PID历史并停车，自动清0；等待下一张尚未处理的新图 |
| `kp` / `ki` / `kd` | 2.5 / 0 / 0 | P/I/D；时间单位为秒，输出单位cm/s |
| `target_y` | 140 | 安全区框中心Y目标，初值取当前 `APP_TASK_ZONE_AIM_Y` |
| `tolerance` | 10 | Y允许±误差，边界包含；不使用正式XY流程的额外滞回或3帧启动条件 |
| `min_speed` | 3 | 非零PID输出的最小速度幅值，cm/s；全零PID不会因它强制移动 |
| `max_forward` | 35 | 前进速度上限，cm/s；初值引用共享宏，0禁止前进 |
| `max_reverse` | 25 | 倒车速度幅值上限，cm/s；0禁止倒车 |
| `integral_limit` | 10 | I项输出的正负限幅，cm/s；输出饱和时不继续向饱和方向积分 |

修改任一控制参数或 `enable`、写入 `reset=1`，都会先停轮并清除历史，只在尚未处理的新图上开始新参数运算；重复图不重新驱动车辆。调参值不会写回Flash，复位/重新下载后恢复上述编译初值。连续图间隔达到500 ms后不继承I/D历史，同毫秒新图不除以0；丢失和重新启用后的第一张图只计算P。

`zone_y_watch` 中观察 `y`（当前归一化中心）、`error`（目标减当前）、`p/i/d`、`raw_speed`（限幅前）、`speed`（两轮共同目标）、`dt`（秒）、`valid`、`in_band`、`frame_id` 和 `view_id`。`valid=0`时 `y/error` 仅保留旧记录。实测轮速观察已有全局变量 `speed_l_measure`、`speed_r_measure`，与目标速度比较。`status`：0禁用、1舵机等待、2等待有效本队整区、3正在控制、4Y在停车带、5参数/队伍无效、6测试到时。

先保持Ki/Kd为0，调Kp确认Y误差和实际速度；若 `raw_speed` 很小且未达到速度上限，增加上限不会加速，应检查Kp与误差；若输出已被前进/倒车上限截断，关注对应上限；若输出长期落在最小速度，关注 `min_speed`。参数确定后需要手动记录；此测试参数尚未接入下方正式安全区XY任务。

### 独立XY＋固定航向测试

实现文件为 `app_zone_xy_heading_test.c/.h`，入口为 `App_ZoneXYHeading_Test(team, fixed_yaw_deg)`。它与独立Y测试、正式按键任务互斥；当前 `main.c` 中入口保持注释，取消该入口注释可切换至此测试。XY目标和PID宏继续引用 `app_task_config.h`，固定航向角只在首次调用时锁存，不随视觉X误差改变。

```text
首次调用建立180秒起点
    ↓ 前框落下、摄像头设为正常观察角，唯一等待500 ms
发送当前view_id，等待本队安全区（红5/蓝6）有效数据
    ├─ 无图、坏图、旧视角或没有本队安全区 → 左轮+15、右轮-15 cm/s原地旋转，继续发送并等待可用数据
    └─ 找到 → 同帧多个本队安全区取第一个，立即进入首次X对准
           ↓ X进入APP_TASK_ZONE_AIM_X±APP_TASK_ZONE_X_TOL
       直接进入XY接近；不增加200 ms/3帧起步、换向或停车带等待
           ├─ Y未到位 → 使用原Y比例速度和X差速PID持续运动
           ├─ Y到位但X超差 → 纵向速度为0，只做X差速纠偏
           └─ X、Y到位且固定航向在APP_TASK_TURN_TOL_DEG内 → 立即停车并保持完成

首次X对准丢失 → 停轮最多APP_TASK_ZONE_ALIGN_LOST_MS（200 ms）；期间找回立即继续，期限到仍无数据则换view_id旋转重搜
XY运动中丢失 → 若此前有纵向速度，保持原航向和实际纵向速度APP_TASK_ZONE_HOLD_MS（300 ms），仍丢失即换view_id旋转重搜；此前速度为0则直接重搜
转向或侧移期间 → 目标暂时离开画面不打断动作；通信/视角数据不可用时按原地旋转规则处理
固定航向未到位 → 按误差方向转90°，以编码器平均行程侧移5 cm，再转回侧移前航向；随后更新view_id，重新做X、Y和航向检查
角度误差实际跨过目标 → 下一次侧移距离减半；±180°回绕不算跨过
    ↓ 以上动作重复，直到三项同时到位或测试累计180秒
到位或180秒到时 → 停车并保持，测试函数继续接管主循环
```

这版不判断转向是否收敛、不判断编码器反向或打滑、不设置单动作超时或重试次数、不做额外确认；除落框500 ms、首次X丢失200 ms和XY丢失期间保持300 ms外，不插入动作切换等待。`zone_xy_heading_watch` 提供阶段、坐标误差、固定/临时航向、侧移行程和左右轮目标速度，便于在线观察调参。它只完成视觉上的安全区XY与固定航向测试，不执行卸货、送达确认或后续捕捉。

### 原有视觉打印与完整安全区测试

主循环在 `Rescue_Usart2_Process()` 更新场景后调用独立头文件 `app_vision_test.h` 中的：

```c
App_Vision_Test(); // 不用时只需注释这一行并重新编译。
```

```text
每次主循环更新视觉缓存
    ↓ App_Vision_Test检查距上次打印是否达到50 ms
    ├─ 未到 → 立即返回，继续原任务
    ├─ 无有效图/图像过期 → 串口1打印“[VISION] no valid scene”
    └─ 有效图 → 打印帧号、视角、原图image分辨率、归一化norm分辨率、检测总数和flags
           ↓ x/w按640宽、y/h按480高归一化，保留1位小数
       逐条打印全部检测的type、conf、中心x/y、框w/h及跟踪id
       继续原任务
```

中心及框尺寸统一换算到640×480：`x=cx×640/原图宽`、`y=cy×480/原图高`、`w=width×640/原图宽`、`h=height×480/原图高`，打印保留1位小数，复用 `APP_TASK_IMAGE_W/H` 参考尺寸宏。首行 `image` 是相机原始分辨率，`norm` 是打印坐标的参考分辨率；例如1280×960原图的中心(640,480)、框(100,80)，打印为 `x=320.0 y=240.0 w=50.0 h=40.0`。原图宽高为0时输出无有效图提示，避免除零。

空场景打印 `count=0`，截断场景仍打印收到的全部条目，`flags` 位 `0x02` 表示相机列表截断。无类型、置信度、视角或任务目标筛选，同一有效缓存图也按50 ms重复打印；无有效图时不打印旧坐标。此调用只读取场景，不控制执行器或发送视角，独立于 `APP_TASK_DEBUG_ENABLE`。串口1使用现有115200、8N1阻塞发送，条目较多时输出及主循环实际周期会超过50 ms。若启用上方带 `continue` 的独占安全区测试，该测试会跳过此处调用；需要同时打印时，将这一行移到 `App_Zone_Test()` 内 `Rescue_Usart2_Process()` 之后并包含 `app_vision_test.h`。

```text
开机测试：原硬件初始化完成，首次调用App_Zone_Test
    ↓ 建立180秒整轮起点，载物标记置1
停车，前框落下90°，摄像头50°，等待500 ms（state=17）
    ↓ 视为已框住绿色且复检通过，不运行捕捉或框内复检
进入下方公共安全区流程

正式模式：上电停车，KEY2蓝方/KEY3红方启动；同时按下优先红方，KEY1只调试打印
    ↓ 首次启动建立180秒整轮起点，重试不重置
前框抬起180°、摄像头50°，双轮20 cm/s直行2秒（state=1）
    ↓ 不先清零轮速、不额外等待
新view_id，左+15/右-15 cm/s持续顺时针旋转找绿色（state=4）
    ├─ 无目标、坏图、空图 → 持续旋转；原启动阶段保留180秒计时例外
    └─ 找到绿色 → 停车，锁定目标，首次X对准及XY跟随（state=7）
           ↓ XY稳定到位
       载物标记置1，前框落下90°，停车等待500 ms（state=9）
           ↓ 摄像头保持50°，新view_id，无额外200 ms等待
       框内复检（state=11）
           ├─ 成功 → 进入下方公共安全区流程
           └─ 失败 → 按下方两次复检恢复逻辑执行
```

正式版和原完整XY测试都通过 `App_Task_Proc()` 执行同一套安全区状态机、同一组控制函数与参数。完整XY测试只改变启动位置。安全区阶段均受180秒整轮时限约束：正式版沿用首次按键起点，完整XY测试从自动落框启动起计时，包含500 ms落框等待。当前独立Y调参不调用此状态机。

## 公共安全区完整流程

```text
已框住物块，前框保持90°，摄像头保持50°
    ↓ 新view_id，不额外等待
state=14：左轮+15、右轮-15 cm/s原地顺时针旋转寻找本队整区
    ├─ 红方只找type=5；蓝方只找type=6
    ├─ 无可用新图/没有本队整区 → 一直旋转，直到找到或整轮到时
    └─ 找到 → 锁定本队整区、停车、复位PID，state=15
           ↓ 下一张新图
首次原地X对准：整区X进入APP_TASK_ZONE_AIM_X±APP_TASK_ZONE_X_TOL
    ├─ 未进入 → 纵向速度0，使用公共视觉PID转向
    ├─ 进入 → 停车复位PID，下一张新图开始XY控制
    └─ 整区丢失 → 立即停车，从首次判定丢失起最多等待200 ms
           ├─ 有效新图找回 → 复位横向PID，恢复首次X对准
           └─ 到期仍未找回 → 返回state=14，新view_id旋转重搜

XY接近：直接共用绿色App_Task_CaptureFollow控制，传入安全区独立XY范围
    ├─ Y误差=目标Y-当前Y；速度=2.5×|误差|
    │      最小调整3 cm/s，前进上限35 cm/s，倒车上限35 cm/s
    │      行驶中用同一横向PID差速纠偏，差速限幅为基础速度绝对值的0.8倍
    ├─ Y进入目标±允许误差 → 停止纵向运动；X超差则原地纠偏
    ├─ 纵向已停止，|Y误差|<Y允许误差+10 → 保持原滞回等待
    ├─ 首次起步/换向 → 停车至少200 ms且连续3张新图方向一致才移动
    ├─ XY同时到位 → 停车，开始下方三图确认
    └─ 整区丢失 → 首次丢失时记录航向，保留此前实际纵向速度（可为0或倒车）
           ├─ 0≤丢失时长<300 ms → 按上述速度保持航向
           ├─ 300≤丢失时长<600 ms → 停车等待
           ├─ 有效新图找回 → 复位横向PID，恢复原XY控制，不重做首次X对准
           └─ 满600 ms仍未找回 → 返回state=14，新view_id旋转重搜

三图确认：保持停车，触发停车的图不计入；从进入确认起总计600 ms
    ↓ 每张有效新图占一次；重复/无效/旧视角图不占次数
每张含本队整区且XY均在独立允许范围内 → 本张成功
有效图没有本队整区，或整区XY超范围 → 本张失败
    ├─ 收齐3张，其中≥1张成功 → state=16，确认完成，持续停车
    ├─ 收齐3张且全部失败 → 返回state=14，新view_id旋转重搜
    └─ 满600 ms尚未收齐3张 → 返回state=14，即使已有1张成功也不提前通过
           新一轮找到整区后，重新从首次X对准开始

state=16：保持停车、前框90°、摄像头50°、载物标记1
    ↓ 不继续处理目标位置变化，不卸货、不进入下一轮捕捉
等待复位；整轮到时可转state=0停车，仍不清除载物锁
```

分界线跟随、分区选择、固定投放路线及后续自动捕捉已从运行代码移除，旧 `app_task_zone.c/.h` 及其构建引用已删除。type=10～14仍是合法协议标签，但当前安全区任务仅使用本队整区5/6，不会因为这些标签出现而切换目标。三图确认不叠加绿色的150 ms停车、连续3张稳定图或6 px漂移要求。

## 参数与读图边界

下方正式/完整XY流程参数位于 `app_task_config.h`。以下四个宏独立于绿色，修改它们不会修改绿色的目标和容差；坐标均归一化到640×480。当前独立Y调参参数见上方RAM变量说明。

| 宏名 | 当前值 | 用途 |
|---|---:|---|
| `APP_TASK_ZONE_AIM_X` | 360 | 整区X目标 |
| `APP_TASK_ZONE_X_TOL` | 10 | X允许±误差；首次对准、横向死区、最终到位共同使用 |
| `APP_TASK_ZONE_AIM_Y` | 140 | 整区Y目标 |
| `APP_TASK_ZONE_Y_TOL` | 10 | Y允许±误差；纵向停车带、最终到位共同使用 |
| `APP_TASK_ZONE_ALIGN_LOST_MS` | 200 ms | 首次原地X对准丢失停车等待；找回即恢复，否则到期旋转重搜 |
| `APP_TASK_ZONE_HOLD_MS` | 300 ms | XY丢失后保持航向和原纵向速度 |
| `APP_TASK_ZONE_STOP_WAIT_MS` | 300 ms | 保持航向后继续停车等待 |
| `APP_TASK_ZONE_CONFIRM_FRAMES` | 3 | 到位停车后检查的新图数 |
| `APP_TASK_ZONE_CONFIRM_HITS` | 1 | 收齐全部新图后所需合格图数 |
| `APP_TASK_ZONE_CONFIRM_MS` | 600 ms | 到位确认总期限 |
| `APP_TASK_ZONE_SPIN_SPEED` | 15 cm/s | 左正右负原地顺时针搜索；与绿色搜索共用 |

范围端点包含：当前X为350～370，Y为130～150。绿色继续使用 `LINE_PID_AIM_X`、`APP_TASK_ARRIVE_X`、`LINE_PID_STOP_Y`、`LINE_PID_STOP_Y_BAND`。横向Kp=0.2、Ki=0、Kd=0，纵向Kp=2.5，速度限制、Y滞回、200 ms/3张方向确认均直接共用原参数。此处描述正式/完整XY测试；独立Y调参入口使用上方RAM参数和独立PID。

安全区沿用专用读图：接收层 `GetScene` 要求有效图及本地年龄<500 ms，任务层再检查当前view_id，以frame_id/capture_ms去重；不额外套用绿色200/300 ms年龄、置信度、截断、ID、尺寸或位移筛选。同帧有多个本队整区时取第一个。正常帧间只维持已有控制；有效新图无本队整区或读图不可用时首次建立丢失起点。重复图不建立正常帧间的丢失、不累计确认、不重置已有丢失计时；缓存超过接收层500 ms期限则成为不可用图并触发丢失。首次X对准的200 ms及XY接近的300/600 ms恢复时长均从首次判定丢失起计，不是从最后图像采集时刻起计。

## 绿色捕捉与框内复检

```text
搜索仅按type=1选绿色，多个候选按框底边更低优先，再按更靠近目标X排序
    ↓ 不检查置信度、相邻或拥挤，不按邻居自动触发撞散
锁定后按类型、可选ID、位移≤70 px、宽高1/2～2倍及歧义条件关联
    ↓ 普通绿色按前后画幅各自归一化，不因分辨率改变直接拒绝
首次X原地对准 → 原XY调速 → X=360±10、Y=422±10
    ↓ 停车至少150 ms，至少3张稳定新图，漂移≤6 px
前框落下（当前90°），同次处理发送新view_id并启动第一次复检；摄像头保持50°
    ↓ 记录落框起点；机械动作与复检共用前500 ms，期间保持到位停车
每次复检限时500 ms：收齐3张有效新图，至少1张区域内恰好一个绿色才通过
    ↓ 框内区域按中心坐标X=230～490、Y=390～450，边界包含，沿用当前宏值
    ├─ 区域外实体不计，安全区/分区等标签不计作实体
    ├─ 多件/非绿色、3张无合格 → 本次失败，保存失败类型及原因
    ├─ 首次提前成功/失败 → 缓存终态，不再读图累计或覆盖结果，落框未满500 ms继续停车
    ├─ 每次达到500 ms仍无终态 → 超时失败，不接纳此时才处理的新图
    ├─ 落框满500 ms且已有终态 → 当次处理成功、重试或恢复，不追加等待
    ├─ 第一次失败 → 新view_id重试，清空计数和终态，从重试开始独立计时500 ms
    │      最多两次；不重复落框、不重复机械等待，第二次提前结束立即分流
    ├─ 第二次多件/非绿色 → 前框保持原状态，平均编码器前推5 cm（5 cm/s）
    │      → 抬框清载物锁，同时单轮5 cm/s顺时针累计转360° → 新视角旋转找绿色
    ├─ 第二次无命中/超时 → 抬框清载物锁，同时双轮-15 cm/s后退1秒 → 新视角找绿色
    └─ 通过 → 首次等落框满500 ms，第二次立即进入公共安全区流程

绿色对准/XY接近/落框前复核的坏图或原目标失配
    ↓ 立即停轮，共同600 ms等待；重复/坏图不累计失配张数或延长等待
    ├─ 连续3张有效新图失配或600 ms到期 → 抬框、15 cm/s后退1秒、新视角旋转重搜
    └─ 期限内找回 → 恢复帧仍停车，下一新图继续原阶段
原50秒对准、15秒接近和整轮期限优先；恢复不重置整轮起点
```

绿色及框内复检要求当前视角、完整有效图，本地年龄<200 ms；扩展帧估算总年龄<300 ms。复检未结束时，坏图/旧视角图沿用原规则清空三图窗口，重复图不累计；已有终态后不再读取后续图像，500 ms超时也不覆盖终态。首次复检计时从落框命令起点开始，视角发送及日志耗时计入期限；主循环跨过500 ms才运行时立即分流，第二次从实际启动时刻计时。启动直行/绿色旋转搜索保留原整轮计时例外；进入跟随后恢复整轮检查，搜索已耗尽180秒时不会重新获得时间。整轮180秒在复检缓存、重试及恢复分支之前优先停车，不重置起点。完整安全区测试直接进入安全区，不使用这个例外；独立Y测试及完整安全区测试入口均不切换。
